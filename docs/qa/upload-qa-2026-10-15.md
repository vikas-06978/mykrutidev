# Upload QA: results

Date: 2026-10-15. Plan: QA_Plan_and_Scripts.md (128 file cases + 30 UI cases). Tool under test: this branch, built with `astro build`, served locally, driven in Chromium (Playwright) through the real upload box on `/kruti-dev-excel-to-unicode/` (Kruti Dev → Unicode) and `/unicode-to-kruti-dev/?mode=file` (Unicode → Kruti Dev).

Rules followed: the generated files are Unicode baselines (U0), not Kruti Dev samples. No Kruti Dev key was guessed and no other converter was used as the answer. Generator success is not a PASS. Where there is no genuine seed or no independently checked Kruti Dev copy (K0), the case is BLOCKED.

## Summary

- File cases (128): PASS 11, FAIL 0, BLOCKED 117, NOT RUN 0.
- UI cases (30): PASS 19, FAIL 0, BLOCKED 5, NOT RUN 6.
- Generators: `verify_generators.py` → `GENERATOR_CHECKS_PASS_ONLY` (converter_tested: false).
- 8 bugs found, all 8 fixed on this branch (below). Unit or e2e tests added for B1–B6 and the B8 summary line; B7 and the B8 size label were checked in the browser only. The FAIL count is 0 only because of these fixes.
- Not proven: that any Kruti Dev text converts correctly. That needs K0 copies checked in the real font (BLOCKED cases).

## Bugs found (all fixed)

### B1. Unicode Hindi inside a Kruti Dev run was changed
- Cases: most of D01–D39 and X01–X43 when uploaded as they are (D02–D05 and X06 happened to survive)
- Steps: Upload fixtures/docx/D01.docx to the Kruti Dev → Unicode page, download, read word/document.xml.
- Evidence (before): `किरण की दृष्टि निर्मल है।` came back `करिण की दृष्टि नर्मिल है।`; the page said "All Hindi text converted". Same in the text box: convert("किरण", kruti-dev → unicode) = "करिण".
- Fix: fontMaps.js: words with a Devanagari letter or sign are Unicode already (no legacy font has such a key) and pass through, with their punctuation. Counted as "already Unicode", not "converted".

### B2. Punctuation inside Unicode text read as Kruti keys
- Cases: T09, T10, T14, T21
- Steps: Upload fixtures/text/T09.csv (Kruti → Unicode).
- Evidence (before): `किरण, मोहन` → `किरणए मोहन`; `"सूची तैयार है"` → `ष्सूची तैयार हैष्`.
- Fix: Same fix as B1.

### B3. UTF-16 CSV/TXT without a BOM turned into rubbish
- Cases: T05, T06
- Steps: Upload fixtures/text/T05.csv.
- Evidence (before): Read as Windows-1252: `Amount` → `।\0उ\0व\0…` with NUL characters, reported "All Hindi text converted".
- Fix: decodeTextFile(): zero bytes on odd/even positions → read as UTF-16 LE/BE; other zero-byte files are refused.

### B4. A .docx named .txt was "converted"
- Cases: D47
- Steps: Upload fixtures/docx/D47.docx.txt.
- Evidence (before): "Converted 278 paragraphs · All Hindi text converted", download D47.docx-unicode.txt of binary rubbish.
- Fix: checkFile(): a ZIP or OLE file with a .txt/.csv name gets "This is not a plain text file…" (7 languages).

### B5. A long line with no spaces took minutes
- Cases: boundary 20971520.txt / .csv (U04)
- Steps: Upload fixtures/20971520.txt (20 MB of "A").
- Evidence (before): No result after 10 minutes. Node: 100,000 letters 14.3 s, 400,000 letters 235 s (quadratic).
- Fix: The e-mail pattern now starts only where an address can start: 400,000 letters 36 ms; the 20 MB file 3.2 s in the browser.

### B6. Two dropped files: the second ignored silently
- Cases: U03
- Steps: Drop two .txt files at once.
- Evidence (before): Only one.txt converted, no message.
- Fix: A note under the file name (7 languages).

### B7. Offline: wrong error
- Cases: U20
- Steps: Load the page, go offline, upload.
- Evidence (before): "Something went wrong converting this file."
- Fix: "The converter could not load. Check your internet connection…" (7 languages).

### B8. Size label and summary said the wrong thing
- Cases: U30, D01, T26
- Steps: Upload 20971521.txt; upload any file with nothing to convert.
- Evidence (before): "20.0 MB" next to "larger than 20 MB"; "Converted 3 paragraphs" next to "No Kruti Dev text found".
- Fix: Size rounds up (20.1 MB); the line says "Checked 3 paragraphs" when nothing was converted (7 languages).

## Open items (need a decision or a real file)

- CSV/TXT have no font. In Kruti → Unicode, lowercase English words not in the word list are read as Kruti keys: `English safe` → `English ेंमि`, `Column0` → `ब्वसनउद0`, `=1+1` → `त्र1़1`, `@name` → `/दंउम` (T01–T24). Needs an owner rule (choose columns, or a stronger English guard). Not changed: a guess here could break real Kruti text.
- 1252 fallback (T07, T08, T32): kept on purpose for Notepad "ANSI" Kruti files; the plan wants a rejection or an encoding choice.
- Font name matching (D48): "Kruti Dev 010 NotRegistered" counts as Kruti Dev. By design today; the plan wants an exact alias list.
- XLSX eligibility (X24, X25, X27): a Kruti Dev font set only on a column/row style, or through the theme font, is not seen by the Kruti → Unicode direction. Needs genuine Excel files to know whether real Excel files do this.
- Tracked deletions (D28): w:delText is left as it is in both directions.
- Hindi download names (U12): need a check in a real browser.
- 16 genuine seeds (D29–D34, D36, D43, D44, X22, X39–X41, X44–X46) and all K0 copies (checked in the real Kruti Dev font) are still needed.

## How it was run

Environment: Linux container, Chromium from Playwright (headless), Node 22, Python 3 (python-docx, openpyxl, Pillow). No Word, Excel, LibreOffice, real phone or screen reader.

1. `python make_docx.py / make_xlsx.py / make_text.py / make_boundaries.py --out fixtures`, then `verify_generators.py`.
2. Each fixture uploaded through the page in a fresh browser context; summary, warning, error, downloads, console errors and every request recorded.
3. `check_roundtrip.py` on U0 vs each output; CSV fields compared separately.
4. The fixes re-run against the same files after a fresh build.
